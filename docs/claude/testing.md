# Tests — the standalone runners and the HTTP suite

**Tests & linting:** No Jest/Mocha/Vitest/ESLint configured — but there IS a pipeline now: `npm run ci` locally, and `.github/workflows/ci.yml` on every PR (see [`ci-deploy.md`](ci-deploy.md)). Integration harness at `test-suite.js` — numbered HTTP tests against a running server. **Do not pin that count here.** It has now drifted twice (the figure read `136` while the file held ~147 `test()` call sites plus ~42 `skip()`, measured 2026-08-26); `test()` and `skip()` both push to `results[]`, so the suite's own printed `results.length` is the only true count and a number written in this file is stale the next time a test is added. Prepare fixtures first, or nearly everything fails at the login on test 2.

**⚠️ The suite WRITES — point the server at a copy, never the live sheet.** Test 46 logs an expense, so this is not a read-only harness. Production's `.env` sets **no `SPREADSHEET_ID` at all**, so `server.js` falls through to its hardcoded production default (`1ey1n0AA…`) — meaning *any* server started without an explicit override (this suite's, a helper script's, a stray `npm start`) writes to the live Dispatch Management sheet. **And never identify a sheet by its title:** the VPS `logisx-staging` process uses a sheet *titled* **"logisx-production"**. Its ID is not production — the title is a leftover from how the copy was made — but read in a hurry it says the opposite of the truth. Check the ID, never the name. The safe local copy, used in the command below, is `156Y5-OUUEZspiY7dRsJZ57iyKWLJAjdVP8a4yw0PMN0` ("Dispatch Management (LOCAL)"). Same class of accident on the port: the suite defaults to **3000, which is production on the VPS** — pass `TEST_PORT` (and the server's `PORT`) to run anywhere else.

**The other half of the test story: the standalone runners `npm run test:unit` drives.** These are plain `node scripts/test-<thing>.js` — **no server, no fixtures, no sheet override, no rate-limit window** — and each exits 1 on failure. They are the only tests you can run on a whim, and several are explicitly load-bearing elsewhere in these docs: `test-db-export-guard.js` (lifts `requireRole` into a bare `new Function`, which is why the CSRF check must stay self-contained), `test-csrf-write-header.js` (pins the two duplicated guard copies identical), `test-invoice-owner-guard.js` (the only authorization coverage on the invoice pdf/submit routes), `scripts/check-ratecon-address-parsing.js` (16 verbatim production addresses locking `cityStateZip()`), plus `test-truck-retirement.js`, `test-investor-expense-scoping.js`, `test-period-lock-queue.js`, `test-payout-carry-freeze.js`, `test-google-timeout-retry.js` (locks the Google API retry-on-timeout behaviour a googleapis major would silently break), `test-eld-feed-staleness.js` (the ELD feed-silence sweep — the alarm on the estimated-pay-basis fallback) and the rest of the money-math set. Added 2026-09-23 and load-bearing the same way: `test-password-change-enforced.js` (the forced-change gate, copied into both guards and pinned identical), `test-login-session-rotation.js`, `test-load-ownership-guard.js` (the three-valued `loadBelongsToDriver()`), `test-jt-cache-isolation.js` (fails if a route writes to the shared Job Tracking cache), `test-image-limits.js` with `test-image-limits-regression.js` (every image guard ahead of its decode), `test-public-form-input.js`, `test-expense-load-window.js`, and `test-deploy-scripts.js`, `test-deploy-record.js` and `test-deploy-live.js` + `test-drift-gate.js` (the deploy lock, exact-SHA deploys, the verified-deploy record, the live commit, the deploy action's steps and the drift gate, run against the real scripts), `test-session-sockets.js` + `test-socket-session-client.mjs` (a socket ends with its session; the client's reconnect ladder), `test-routemate-vehicle-sync.js` (the list-outage handling) and `test-invoice-week-selection.js`, which also covers the undated-load ledger. **Run the ones covering what you touched before reaching for `test-suite.js`** — they are seconds, not a 15-minute window. ⚠️ **`ls scripts/test-*.js` under-reports.** The runner takes every `scripts/` file matching `^(test|check)-.*\.(js|mjs)$`, so it also picks up the `scripts/test-*.mjs` client-logic runners and `scripts/check-ratecon-address-parsing.js` — which is the load-bearing one named two sentences up. `node scripts/run-unit-tests.js` prints the authoritative list.

**The suite cannot be run twice inside 15 minutes** — it exhausts its own rate limiters (`exportLimiter` is 20/15min), so a second back-to-back run returns 429 across the export and statement tests and looks like a regression. Wait for the window, or compare against a run from the same cold start. Covers auth, role gating, debug-endpoint auth, webhook secret, chat file validation, canceled-load exclusion. Exits 1 on any failure. When editing `server.js`, run `node --check server.js` before committing (one file — a syntax error anywhere breaks the whole app).
